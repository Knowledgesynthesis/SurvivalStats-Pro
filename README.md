# SurvivalStats Pro

An interactive course in survival (time-to-event) analysis. Twelve modules run from censoring to machine learning. Every curve, test and model is computed live in the browser by a statistics engine whose output matches R `survival` 3.5.8.

## The course

| Part | Module | Interactive labs |
|---|---|---|
| I · Foundations | 1. Time, events and censoring | Calendar vs analysis time; bias of naive censoring handling; hazard-shape explorer (5 families); informative dropout |
| | 2. Kaplan–Meier and Nelson–Aalen | Hand calculation on the Freireich 6-MP data with per-cell checking; KM simulator (CI scales, medians, reverse-KM follow-up); delayed entry |
| II · Comparing groups | 3. Log-rank, weighted tests and RMST | Log-rank step by step; power of log-rank/Wilcoxon/FH/RMST under PH, delayed, waning and crossing effects (Monte Carlo); RMST; Schoenfeld/Freedman trial design |
| III · Regression | 4. Cox regression | Partial likelihood as a risk-set lottery; fitting against known truth; HR → absolute risk; CI coverage over 100 trials; Breslow vs Efron ties; non-collapsibility |
| | 5. Non-proportional hazards | Scaled Schoenfeld residuals vs the true β(t), log-log plots, Grambsch–Therneau test, piecewise HRs; frailty-induced HR drift |
| | 6. Parametric and flexible models | AFT vs PH; five MLE fits and their extrapolations against a known truth (incl. a cure fraction) |
| IV · Beyond one event | 7. Competing risks | Aalen–Johansen CIF vs 1 − KM; cause-specific vs Fine–Gray HRs |
| | 8. Immortal time and landmarking | Naive vs landmark vs time-dependent Cox; conditional survival |
| | 9. Recurrent events | MCF; Andersen–Gill (naive vs robust SE), PWP, first-event analysis under frailty |
| | 10. Multi-state models | Illness–death model: exact occupation probabilities vs Aalen–Johansen |
| V · Prediction | 11. Prediction and validation | Harrell/Uno C, calibration plot/slope/O·E, IPCW Brier and IPA under shifted baseline risk and case mix |
| | 12. Machine learning | Overfitting with noise predictors; ridge-penalised Cox and the λ path |

Each module states objectives and prerequisites. It mixes predict-then-check prompts, inline questions, R and Python code, and a 5–7 item checkpoint; passing at 80% marks the module mastered. The site also has a **Which method?** decision guide, a randomised **final exam** drawn from a 72-item bank, a **glossary** of 75 terms, and a **bibliography** with DOIs, including CONSORT 2025, TRIPOD+AI (2024) and PROBAST+AI (2025).

## Validation

`tests/engine.test.ts` compares the engine with R 4.3 / survival 3.5.8 output, using fixtures generated by `tests/reference/make_fixtures.R`. Agreement is typically 1e-7 or better for:

- Kaplan–Meier estimates, Greenwood SEs and log, log-log and plain CIs; medians and their CIs; RMST and its SE; left truncation
- Log-rank tests (2 and K groups, stratified, Fleming–Harrington ρ = 1)
- Cox models: Efron and Breslow ties, strata, (start, stop] data, robust clustered SE, ridge penalty, baseline hazard, Schoenfeld and martingale residuals, the Grambsch–Therneau test
- Aalen–Johansen CIF and multi-state occupation probabilities; Fine–Gray (`finegray` + `coxph`)
- Exponential, Weibull, log-normal and log-logistic MLEs (`survreg`), and Gompertz (`optim`)
- `pnorm`, `qnorm`, `pchisq`, `lgamma`, `lowess`

`tests/edge.test.ts` covers degenerate inputs: all censored, a single subject, a group with no events (monotone likelihood), no competing events. `tests/scenarios.test.ts` checks, by simulation, that each lab shows what its text claims (e.g., KM unbiased under independent censoring, biased under informative censoring; immortal-time bias; Aalen–Johansen matching the exact CIF).

## Development

```bash
npm install
npm run dev        # http://localhost:5173
npm test           # 44 tests (engine vs R, edge cases, lab behaviour)
npm run build      # type-check + production build to dist/
Rscript tests/reference/make_fixtures.R   # regenerate R fixtures (needs survival, jsonlite)
```

Stack: React 19, React Router 8, Vite 8, TypeScript 7, Tailwind CSS 4, Zustand 5, KaTeX, d3-scale/d3-shape (custom SVG charts), Vitest, and vite-plugin-pwa (works offline after first load). Progress is stored in `localStorage` only.

```
src/
  lib/stats/        survival engine (km, logrank, cox, parametric, competingRisks, multistate, validation, design, …)
  lib/scenarios.ts  data-generating mechanisms for the labs, with exact truths
  components/       charts (Plot, Swimmer, Forest), lesson blocks, checkpoint, layout
  content/          curriculum, question bank, glossary, references, datasets
  pages/            home, 12 module pages, exam, decision guide, glossary, references, progress
tests/              vitest suites and R fixture generator
```

## Deployment

`vercel.json` builds with `npm run build`, serves `dist/`, and rewrites client-side routes to `index.html`. Pushing to `main` deploys through the Vercel GitHub integration.

## Data

All lab data are simulated. The one exception is the Freireich et al. (1963) 6-MP remission dataset, a published teaching dataset used in most survival textbooks. The course is for learning, not for clinical decisions.
